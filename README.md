# Pufu Lens

気になった記事や自分のメモを集め、問いを深め、行動につなげるためのアプリです。

Web・Xの投稿のURLやテキストをプロジェクトごとにストックすると、AIが要約と問いを生成します。集めた情報から関心や知識を「メモリ」に整理し、問いを解決するための「プ譜（プロジェクト譜）」を作成・編集できます。

## できること

- **集める** — URLやテキストを保存。iPhoneのショートカットやMCPからも追加できます。
- **読み返す** — 要約・本文・メモを確認し、検索やお気に入りで探せます。
- **考える** — AIが生成した問いや、自分で追加した問いを蓄積できます。ストックなしの問いも保存できます。
- **つなげる** — プロジェクトごと、ユーザー全体の関心と知識をメモリとして更新します。
- **行動にする** — 問いに対する課題を入力してプ譜を生成。編集と振り返りを局面として保存できます。

Googleアカウントでログインし、初回にニックネームを入力して利用規約・プライバシーポリシーへの同意を完了すると利用できます。Googleのメールアドレス・名前は保存・利用しません。記事・問い・メモリ・プ譜はユーザーごとに保存されます。

## まずはローカルで試す

**Node.js 22.22.3以降の22系、または24.11以降（推奨24系） / pnpm 11.28.6** を使用します。Corepackを使う場合は、初回に `corepack enable` を実行してください。

```sh
pnpm install --frozen-lockfile
pnpm run setup
pnpm run dev
```

[http://localhost:5173/](http://localhost:5173/) を開き、「ローカルデモを開く」を選びます。CloudflareやGoogleの認証情報なしで試せます。

デモにはサンプル記事が含まれます。AI未接続時は本文の抜粋や定型の案を使い、保存からプ譜の編集までの流れを確認できます。本物のAI生成を試す場合は、[Workers AIの設定](docs/SPEC.md#ローカルでworkers-aiを使う)を参照してください。AIへ送った資料はCloudflareで処理され、利用量に応じて料金が発生します。

プ譜生成のモデル設定や処理の詳細は、[詳細仕様](docs/SPEC.md#プ譜)を参照してください。既定のモデルにはWorkers PaidまたはAI Gatewayの前払いクレジットが必要です。

## 基本の使い方

1. プロジェクトを作り、「記事をストック」からURLまたはテキストを保存します。
2. 要約を読み、生成された問いを確認します。「問いを追加」から自分の問いも残せます。
3. 問いの詳細で「問いの解決を考える」を選び、実現したいことを課題として入力します。
4. 「プ譜を作成」で案を生成し、編集・保存します。局面を追加すると、編集と振り返りを続けられます。

プロフィールの自己紹介やプロジェクト概要は、メモリ生成の背景情報に使います。プ譜は選択した問い・ストック、明示入力とプロジェクト概要を参照し、個人・プロジェクトのメモリは生成AIへ送信しません。

退会は「プロフィール」から行えます。登録データ・保存本文を削除し、全端末のセッションと連携を無効にします。削除したデータは復元できません。[退会について](docs/SPEC.md#退会)を参照してください。

詳しい操作は、アプリ内の「ユーザーマニュアル」を参照してください。

## 外部サービスとの連携

- **iPhone** — 共有シートから記事を保存できます。[ショートカットの設定](docs/SPEC.md#iosショートカット)を参照してください。
- **ChatGPTなど** — MCP連携でストックや問いを追加・検索し、保存済みのプ譜をJSONや画像で確認できます。[MCP連携の説明](docs/SPEC.md#mcp連携chatgptなど)を参照してください。
- **AIクライアント用スキル** — Codex CLIやClaude Codeなどで、複数ストックと既存の問いから問いを深めたり、状況を相談しながらプ譜を育てたりできます。[配布スキル一覧](skills/README.md)を参照してください。導入手順はアプリ内マニュアルの「スキルで問いを深め、プ譜を作る」にあり、「外部連携」からも開けます。

### X連携

「外部連携」でXのAPIトークンを登録すると、投稿URLから本文を保存できます。Xの開発者契約・読み取り権限・利用枠が必要です。取得できない場合は、ストックの詳細画面で本文を貼り付けて補完できます。[X連携の詳細](docs/SPEC.md#x連携)を参照してください。

### YouTubeの動画を表示する

動画URLとメモを保存し、一覧のサムネイルから詳細画面を開いて再生できます。再生できない場合は「YouTubeで開く」からご覧ください。

動画内容の取得や自動要約・問いの生成は行わず、自分で書いたメモだけをメモリに反映します。サムネイルやプレーヤーの表示・再生時にはYouTubeへ通信します。[動画表示と取得範囲の詳細](docs/SPEC.md#記事取得の範囲)を参照してください。

## プロジェクトの公開

プロジェクトの「設定」→「公開設定」で公開できます。初期状態は非公開です。公開すると共有用URLが発行され、ログイン前のトップページにも掲載されます。

- プロジェクト名・公開用の紹介文、ストックのタイトル・URL・要約・要点・トピック、問い、プ譜の各局面と振り返りが公開されます。
- メモリ・個人メモ・取得本文・内部用のプロジェクト概要は公開しません。ただし、プ譜そのものに書いた内容は公開されます。
- 公開後の追加・編集も反映されます。非公開にするとトップ掲載とURLからの参照が停止します。

公開前に内容を確認してください。[公開範囲と設定の詳細](docs/SPEC.md#プロジェクトの公開)を参照してください。

## ブラウザーE2Eの実行

`pnpm run e2e:ci` でストック保存、プ譜の編集・局面、プロジェクト公開を、実アプリと使い捨てDBで確認します。ローカルのCodexによる操作記録と、AIを使わないCI再生を分けています。初回のブラウザー準備や変更時の手順は [E2Eの説明](packages/e2e/README.md) を参照してください。

## プフィのフィードバック保守

会話と検知理由はD1の`usability_feedback`に保存します。既存Workers AI bindingがあれば、概要・再現手順・期待/実際の動きを整理します。AI未設定・失敗でも会話を保存し、保守側で確認できます。GitHubの設定は不要で、外部登録や通知は行いません。

保守エージェントは [.agents/skills/review-feedback/SKILL.md](.agents/skills/review-feedback/SKILL.md) の手順で未確認の内容を読みます。`pnpm feedback:review`はローカルDB、`pnpm feedback:review --remote`は本番DBを明示的に読み取ります。本番は通常のproductionビルド後の設定とCloudflare D1の管理権限が必要です。自動実行のスケジュールは設定しません。

`title`・`summary`・`reproduction_steps`・`expected_behavior`・`actual_behavior`が保守用の整理結果、`conversation`がユーザーとプフィの会話、`detail`が原回答です。`status`は`pending`（整理中）、`needs_info`（任意の返事待ち）、`awaiting_review`（保守待ち）、`held`（秘密情報等で要注意）。途中で会話を閉じた`needs_info`も確認対象です。`review_status`は最初`unreviewed`で、担当者が確認したものだけ`reviewed`に更新します。保守向けの一般ユーザー用API/MCP公開はありません。

プフィの常設入口はログイン済みのユーザーマニュアルだけです。右下のアイコンの左に「何かお困りですか？」を表示します。他のログイン後の全画面では、下記のトラブルが繰り返されたときだけ案内します。「声かけを受け取る」の設定はありません。

| 条件（直近120秒）                                                            | 点数 |
| ---------------------------------------------------------------------------- | ---- |
| 同じコントロールを16秒以内に4回クリックし、1秒待っても画面や処理の反応がない | 3    |
| 同じ項目・操作の入力エラーが2回／3回以上                                     | 2／3 |
| 同じAPI操作の失敗、または通信・サービス障害が同じ分類で2回                   | 3    |

合計3点以上で候補になります。同じ理由は最大点だけを採用し、成功すると関連するコントロール・入力項目・操作の履歴を解除します。通常の画面表示、局面の往復、機能の開閉、待機では発火しません。入力・処理・初回登録中、非表示タブ、オフラインでは案内を控えます。自動表示は1セッション／24時間1回まで、「大丈夫です」の後は7日休止します。操作の入力値・URLの識別子・生ログは自動送信せず、検知理由と固定の画面IDだけを送信時に添えます。

「操作に迷いました」では、実際のマニュアル本文を見出し→小見出し→本文のツリーにし、Cloudflare **Clef**の型付き選択で辿ります。上位の見出しには子項目の補足を付け、本文をClefの`state`へ渡します。判定用の選択肢は短い見出しだけにします。ログイン手順は独立した本文として案内します。単語検索やベクトルDBは使いません。`wrangler.jsonc`の`AI_MANUAL_MODEL`は既定`@cf/cloudflare/clef`で、`@cf/cloudflare/clef-flash`も指定できます。既存`AI_MODEL`（Gemma4）は会話の整理用です。AI未設定・失敗・曖昧な判定なら、利用者が実際の見出しを選択できます。表示する回答はマニュアル本文の抜粋と該当箇所へのリンクです。

案内後に「お役に立ちましたか？」を確認します。未解決なら検索し直さず、解決しなかった部分を伺います。検索だけでは会話をDB保存しません。未解決の返答を明示送信した時は、返答全文と最初の質問・案内先を分けて保存し、既存の追加確認・保守レビューにつなげます。

マニュアルのAI判定は本人30回／全体300回を24時間の上限とし、既存の共通AI呼び出し枠も使います。`0050_manual_search_usage.sql`の匿名集計はアカウント削除で全体上限を回避させず、質問本文を保存しません。会話の送信は本人3会話／全体60会話を24時間の上限とし、同じUUID/roundの再送を重複処理せず、追加確認は最大2問です。保守側は会話を命令として扱わず、コードと再現手順を確認して通常の修正PRを作成します。詳細は[表示・マニュアル案内の設計](docs/superpowers/plans/2026-11-12-pufi-display-conditions.md)を参照してください。
