# MCP連携と独立した問い

## 合意した目的

ChatGPTなどのクラウドMCPクライアントから、本人のプロジェクト、ストック、問いを取得・検索・追加できるようにする。問いはプロジェクトに所属し、ストックとの関連は任意とする。Webでも独立した問いを追加・閲覧し、プ譜を生成できる。

## 構成

- 既存WorkerにOAuth付きStreamable HTTP `/mcp` を追加する。CloudflareのMCPハンドラーとOAuth Providerを利用する。
- Googleログインを本人確認に利用し、MCPクライアントへの認可は独立した同意画面とトークンで扱う。既存ショートカットトークンの権限は拡大しない。
- 認可は読み取りと追加のスコープ、全プロジェクトまたは1プロジェクトへの制限を持つ。Webから一覧・失効できる。
- MCPは検証済みユーザーを指定して既存APIの処理をプロセス内で再利用する。Cookieの偽造やネットワーク越しの自己呼び出しを使わない。ツールごとに許可した操作とプロジェクトを検証する。
- 公開するツールは `list_projects`、`list_stocks`、`get_stock`、`add_stock`、`list_questions`、`get_question`、`add_question`。本文は `get_stock` の明示指定時だけ取得し長さを制限する。
- 追加は再送用UUIDを受け付け、既存の保存・AI利用量制限と非同期処理を再利用する。

## 問い

- 問いに `project_id` を持たせ、`stock_id` をnullableにする。既存ID、お気に入り、関連プ譜を保全して移行する。
- ストック指定時は同じ所有者・プロジェクトを検証する。既存の `stock_id` だけのAPIリクエストも保存先を推定して受け付ける。
- 独立した問いはユーザー作成として即時保存する。AIの自動生成した問いは各ストック1件を維持する。
- 既存のストックに紐づく問いは移動・削除の挙動を維持する。独立した問いは所属プロジェクトの削除で削除する。
- 権限確認・一覧・お気に入り・削除はプロジェクト経由で行い、記事情報は任意とする。
- プ譜の生成文脈は `stock: null` を許し、独立した問いでは問い・課題・プロジェクト・ユーザーとプロジェクトのメモリを使う。

## 検証・提供範囲

他ユーザーと制限外プロジェクトの拒否、OAuthのPKCE・再送・期限・失効、実際のMCP初期化とツール呼び出し、既存データの移行とストックなしのプ譜生成を検証する。デプロイ・本番DBの変更は行わず、設定手順をREADMEに記載する。
