# プフィとの会話と保守向けDB保存

プ譜画面で困った利用者にプフィが短く声をかけ、会話から改善のヒントを受け取る。ユーザーの修正指示に基づき、Issue自動登録とGitHub連携は取り除く。会話と整理結果はD1に保存し、保守エージェントが確認する。

- 自動検知時は「ちょっと困った？」と「うん」「大丈夫」。入力中・処理中は表示しない。
- 会話は短い選択肢とひとことの返事。フォームの長い説明・同意チェックボックスは使わず、送信前に保存/AI整理への同意を短く表示する。詳細は設定から開く。
- 足りない情報だけを1問ずつ、最大2回まで任意で確認する。「ここまでにする」で送った分を保守待ちにする。
- 検知の既定は無効。ブラウザー同意、1セッション/24時間1回、拒否後7日休止を保持。
- 画面/操作の固定IDのみ自動取得し、編集内容・入力値・生ログは送らない。会話の所有者を初期アカウントに結び付け、他タブでアカウントが変わったら再送を拒否する。
- D1に会話を先に保存。AIで概要・再現手順・期待/実際の動きへ整理し、保守確認待ちにする。AI未設定・失敗・秘密情報なども保存して人の確認に回す。
- UUID/roundのCASで再送と追加回答を重複させない。退会時は会話/整理結果を削除し、処理中のAI応答でも再作成しない。
- 保守用のCLIは管理者のD1権限で読み取る。一般ユーザーのAPI/MCPに一覧を公開せず、自動スケジュール・外部登録・本番反映は行わない。
- プフィは首元の青い布に虫眼鏡マークがある参照画像を基準とし、陰影を抑えた平面的な2Dアイコンを使う。

検証: 検知/頻度、会話/再送/終了、所有者変更、DB整理結果、AI失敗/未設定、退会競合をVitestで確認。実際の取込エラー反復と局面往復で検知を発火させ、PC/スマホ幅のlight/darkで検知時と会話中を撮影する。共通API変更なので関連E2Eは全ケースを実行。最終差分のquick scoped監査と同一モデルによる独立レビュー後、PR #218を更新する。

最終検証: Vitest 121ファイル・1369件成功。CIモード関連E2Eは全13シナリオ×2幅の26件成功。2Dアイコン差し替え後の検知/会話も両幅で再撮影し2件成功。型（root/E2E）・lint・整形・最終ビルド成功。quick scoped監査で見つかった退会時の全体quota回復は匿名受付履歴で修正し、独立検証と再レビュー済み。保守CLIの本番実行・実AIの品質・iPhone実機は未確認。
