# プフィの気づきフィードバック 実装計画

ユーザー提示のMVP仕様に基づき、Reactのプ譜画面からD1保存・Workers AI判定・GitHub Issue起票まで実装する。GitHub送信先は環境変数で管理する。首元の虫眼鏡マークを含む提供キャラクターを基準にする。

- [x] 60秒の重複しないスコア、4クリック/8秒、局面往復、入力エラー反復を実装。反応通知で連打候補を解除する。
- [x] 明示的なブラウザー単位の同意、セッション/24時間制限、拒否後7日休止、入力/通信/初回ガイド中の抑止を実装。
- [x] 回答・固定IDのみを認証済みAPIに送信。D1に先に保存し、不明確・未設定・検索失敗・AI失敗は保留。再送IDで重複を防ぐ。
- [x] GitHub検索結果をAIに提示し、重複はD1で既存Issue番号に集約。起票の検索〜書込はD1ロックで直列化。外部書込の自動再試行は行わない。
- [x] 検知・頻度・APIの成功/重複/保留/同意/認可/送信上限をVitestで検証。実ブラウザーで手動送信と編集モーダル内UIを両幅確認。
- [x] 日英の操作説明・プライバシー説明・連携設定と保留の運用手順を更新。
- [x] 型・lint・テスト・ビルド・関連E2E、差分のquick監査と独立レビューを実施。
- 最終工程: 検証済みブランチをpushし、mainをベースにPR作成。

実装判断: MVPはPostHog不要。停滞の補助判定・API障害による加点・改善結果通知は対象外。往復はプ譜の局面切替で検知し、往復だけでは表示しない。既存プ譜内容、ユーザー識別子、画面URL、DOMテキスト、入力値、クリック位置は自動送信しない。サーバーは1利用者24時間3件・全体60件に制限する。既存Issue候補が100件を超える場合は不完全な検索と扱い保留。

レビュー重点: 正常応答後の誤検知、入力中の表示、複数タブの頻度、再送と同時起票、AIの不正なIssue番号や情報の公開。外部AI/GitHubへの実通信はテストでは行わず、実環境の品質・権限は未検証と明示する。

追加要件: 情報不足なら固定の質問種別をAIが選び、1問ずつ最大2回確認する。任意で終了可能。追加回答は同じ送信IDとroundのCASで保存・判定し、再送しても重複しない。

独立レビュー: 重複検索とAI使用量予約、picker応答通知と同意解除同期の指摘を修正し再レビュー済み。監査で見つかった退会中の競合は、公開直前の回答・所有者の存続確認と削除済み410応答を追加。ローカルの回帰テストで失敗を再現後に修正を検証した。

最終検証: Vitest 121ファイル・1370件成功。CIモードE2E 13シナリオ×2画面幅、26件成功（skip/AIモデル消費0）。root/E2E型チェック、lint、整形、最終Viteビルド成功。監査はsource-onlyのquick scoped run（追加coverage 1件をdeferred、過去領域は対象外）。実GitHub/AI、iPhone実機は未確認。
