# E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Codexによるローカル操作・記録と、AIを使わないCIで主要なユーザー操作を保護する。

**Architecture:** 独立したE2Eワークスペースにtester-army/e2eとWebエンジンを固定導入する。専用ランナーが使い捨てのローカルWorkers環境を起動し、シナリオ対応表から対象を選び、実行結果を照合して終了・清掃する。

**Tech Stack:** Node.js 24、pnpm、e2e、Playwright、Cloudflare Workers/D1/R2/KV、Vitest。

**Spec:** docs/superpowers/specs/2026-10-30-e2e-design.md

## Global Constraints

- Codex側でAI利用、CIはAIを使わず実行。両方で同じexpectを使う。
- 本番・外部記事・Workers AIに接続しない。ローカルデータとポートを分離する。
- 公開済み依存を固定。既存Vitest/品質検査を維持する。
- 記録不足・未実行・AI使用はCIを失敗させる。結果と制約をPRに明記する。

## Review Focus

- CIでAI設定/認証やローカル環境変数が紛れ込んでもAIを起動しない。
- キャッシュ不足・未実行・一部スキップを成功と扱わない。
- 並列実行・異常終了時も他の開発データを破壊しない。
- 公開前の確認・非公開化後の匿名アクセス・既存局面の保持を実際の保存先まで確認する。
- 共通ファイル変更を関連実行から落とさず、対応表の不整合を検出する。

## Execution ledger

- 実装方式は会話の合意とAGENTS.mdに基づく継続実行。追加の承認待ちは設けない。
- 初期調査：Codex CLI 0.159.2はChatGPTでログイン済み。e2e 0.21.3/Web 0.15.3は公開後24時間以上。
- 配布確認：公式mainの資料にある @e2e-dev/acp はnpmで404。公開済みSDKとCodexアダプターで実現できる方法を確認する。

- 実装判断：公式ACPが未公開のため、公開StepExecutor＋CodexCLI限定JSON操作を採用。初期記録はローカル専用bootstrapの実操作と同じexpectで生成。CIはdeny executorを必ず使い、strictキャッシュ単独へ依存しない。
- 検証：3シナリオ×desktop/phoneの6件がbootstrapとCI再生で成功。別の新規DB・ポートでも全件再生成功、model calls/tokens=0。記録を1件除くとblocked/0AIで失敗。ポリシー/台帳/レポート/JSON操作境界24件を含む既存全844件が成功。
- CodexCLI0.159.2は認証済みだが、実UIでのrecordはモデル接続失敗で60秒後に失敗。15秒のダミー画面でもモデル接続失敗。ライブAI成功は未確認として残し、失敗をbootstrapで成功に見せない。
- ブラウザーCDNは実行環境の通信制限により403。既存Chromiumを専用profile/CDPで使用。GitHub Actionsの標準ブラウザー実行はPR上で確認する。
- 依存追加時の不要なoptional peer更新を除去し、既存アプリ依存グラフを保持。新e2eのZod4.6.1はhigh advisoryを検出したためe2e>zod4.6.7の限定overrideで修正し、frozen installと依存監査成功。
- マニュアル影響：開発基盤のみの追加。利用手順・公開範囲・利用条件は変更せずUserManual.tsxは更新しない。

- 最終coverage criticが独自loopback CDPの別OSユーザー境界を追加確認対象にしたため、ユーザー要件にないシステムChromium/CDP代替起動を削除。ブラウザーは公式SDKの通常起動のみとし、最終構成のブラウザー実走はPRのGitHub Actionsで確認する。既存ビジネスフロー6件のローカル検証と、この通常起動の検証を区別する。

- 最終監査：4unit covered、45unitは対象外。候補0件、両validator成功。追加のlocal IPC確認を経て独自CDP補助起動を除去し、source上で公式SDKのprivate pipe/profile/cleanupを確認。同じモデルの独立レビューは3回、残る指摘なし。
- 最終の全Vitestは79ファイル844件成功（159.56秒）、型/lint/整形/build成功。途中で既存mcp-registrationのnative limiter件数テストが一度11件許可となった。Miniflareは固定1分窓を用い、テストは同一窓内との条件を固定していない。期待値や製品コードは変更せず、単独6件と全844件を再実行して成功した。観測した既存の時刻依存はPRへ明記する。
