# 中間目的と八要素を統合した勝利条件 Implementation Plan

**Goal:** 全中間目的の成果と廟算八要素を考慮して、成就した全体の状況を表す勝利条件を生成する。

**Spec:** 本会話の調査結果に対する「修正お願いします」。テストの作品名は一般名称を使用する。

**Architecture:** 本文抽出→目標・中間目的構成→勝利条件統合の3段階。最後の段階には確定済みの全中間目的と八要素の構造を渡す。全目的の寄与と全八要素の扱いを短い構造化出力で確認し、完成文だけを既存scoreへ保存する。単語一致で意味の網羅を保証したとは扱わず実モデルも照合する。

## Constraints

- 保存済みプ譜・公開形式・画面レイアウト・ユーザーの目標は変更しない。
- 各段階は既存aiStepの利用枠・世代・削除guardとcacheに従う。通常3calls、行動なしは勝利条件生成を省略。
- 最後の工程中心の指示と作品固有の例文を除去。全目的が必要な関係を統合し、工程を列挙しない。
- 八要素にない条件や、不明な予算・期間・競合等を作らない。記事の例示期間は利用者の期限に変えない。
- 勝利条件は1文・日本語60字/英語140字、統合入力24KB・出力2000tokensを維持。

- [x] `server/pufu-plan.ts`を中間目的までの構成にし、`server/pufu-win.ts`で最終統合。`server/pufu.ts`に別aiStepを追加。
- [x] 既存fixtureと3段階の計数・cache・削除テスト、README/仕様/利用者説明/E2E台帳を更新。
- [ ] 一般名称の日本語/英語・制約付き・曖昧な資料を実モデルで照合し、型/lint/format/全Vitest/build/E2Eを確認。
- [ ] standard scoped監査・同モデル独立レビューを完了し、コミット・push・main向けPRを作成。

## Review focus

- 統合中に失敗・利用上限となっても未完成を保存せず、抽出/中間目的を再送しない。
- 全目的への参照が揃っていても意味が統合されたとは限らないため、実モデルの成果を独立確認。
- 全八要素を参照可能にすることと、全項目を文章へ列挙することを区別する。
- 特定作品の事例、別案件、未採用案を全体の条件へ昇格させない。
- 認可・削除・世代変更のguardを統合段階にも適用する。

## Decisions and verification

-

+- 八要素の評価はroleとsourceElementsを返す。分類が混ざった場合も別項目の既知情報を参照できるが、unknown以外は非空入力への参照が必須。未知の情報や空欄を根拠にできない。
+- 条件の数値は必須構成語にせず、目的の成果を結びつける状態文を作る。試行や判断材料から本運用の実施・継続改善へ広げない。
+- 作品名はすべて一般名称。映像修復の架空記事、窓口の制約付き固定事実、日本語/英語の目的・統合を実モデルで照合する。
+- 手引きの日英の生成説明に通常3回のAI呼び出し利用枠を使用することを追記。外部APIや公開権限・保存score形式の変更はない。
+- ローカルE2Eは公式Chromium取得先への通信が環境ポリシーで403となり起動不可。合格とは扱わずGitHub CIで確認する。
