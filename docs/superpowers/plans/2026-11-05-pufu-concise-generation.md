# 簡潔なプ譜生成の回復 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 引用集になった生成結果を、短い獲得目標・勝利条件・中間目的・施策・廟算八要素からなるプ譜へ直す。

**Architecture:** 原文完全一致の引用をノード本文へ転記する処理を廃止し、AIが資料を要約・構造化した短文を受け取る。生成コメントはサーバーで常に空にし、参考事例・出典・仮説等の注記を追加しない。取得処理・参照数・AI回数を維持し、モデルと入力枠は実生成の評価結果に基づき見直す。

**Tech Stack:** TypeScript / Cloudflare Workers AI / Zod / Vitest / 既存E2E

**Spec:** 本チャットのユーザー訂正（コメント不要、参考情報不要、八要素を具体化、記事にない新規施策を追加しない）。

**内部の根拠処理:** GLM-5.3の施策と八要素は、一時的な根拠区間IDと表示用の短文を別々に生成する。IDはサーバーが本文・明示入力に付与し、実在を照合して保存前に破棄する。原文転記は生成結果へ強制しない。ID照合は文章の意味一致まで決定的に保証するものではなく、実モデル評価で確認する。

## Global Constraints

- 自動生成ノードのcomment.textは全て空。ユーザーが保存・編集したコメントは変更しない。
- 各ノードは資料の引用や説明ではなく、成果物・状態・行動・現在の条件を短く記載する。
- 目標と問いが空なら記事中の取り組みをプロジェクトとして整理する。利用者を記事の読者に固定して「記事を理解する」計画へ変えない。
- ユーザー入力の獲得目標・条件は優先し、記事中の他案件の金額・期間をユーザー条件へ転用しない。
- 八要素は要約・文脈の整理を許容し、根拠がなければ空欄。全てを未確認という定型文に置き換えない。
- 問い/ストック各1件、生成AI1回、既定モデルの入力40000 UTF8 bytes（旧モデルは24000）、出力最大6000 tokensを維持。
- 既存の保存済みプ譜を書き換えない。mainへのマージ・本番反映はしない。

## Review Focus

- 原文と異なる簡潔な言い換えを受け入れ、資料IDや完全一致の欠如で八要素を落とさない。
- 施策は入力・本文にある取組の要約に限定し、未実施・否定された活動を追加しない。
- 生成コメント・参考事例等の注記が残らず、ユーザーが書いたコメントの保存経路は維持。
- 詳細上限と長文資料で本文枠を保持し、推測した目標は具体的な得たい成果を示す。
- 実モデルの出力を固定チェックリストで評価し、mockだけで品質改善を主張しない。

## 実生成の評価基準（固定）

1. [critical] ノードのコメントは空で、参考事例・出典・仮説などの注記や長い引用がない。AI短文は各240文字以下。
2. [critical] 目標は得たい成果、勝利条件/中間目的は状態、施策は具体的な行動。記事のみの例も記事の読書感想/理解計画へ置き換えない。
3. [critical] 入力/資料にない活動・否定された活動を施策へ加えない。入力済みの目標・人数・予算・期限を保持する。
4. 本文が十分な記事/明示条件の例は八要素5項目以上を具体化し、人・品質・役割・環境・時間等の資料の条件を反映。乏しい資料は不明な要素を空欄とし数字を創作しない。
5. リマスター記事では作品本来の表現の保持と、依頼者/監督と修復側の方針調整を反映。明示条件例では窓口・台帳・引継ぎを反映。
6. 問い/ストック各1件、AI1回・モデルごとの入力上限を維持し、結果はPufuScore schemaを通る。英語holdoutでは入力目標を保持し生成部分を英語にする。

## 実評価からの設計修正

- 旧QwenとGLM-4.7-Flashでは繰り返し生成時に条件の施策化などが残ったため、プ譜専用モデルをGLM-5.3-Flashへ分離。思考量は通常low、目標も問いも空の記事ではhighとして親目的と施策の方針を照合する。1呼出し/6000出力token上限を維持する。Workers PaidまたはAI Gateway前払いクレジットが必要。単価は入力$0.15/出力$0.50 per million tokens（旧Qwenの約2.9倍/1.5倍）で、実使用量は入力と生成量による。本番反映はこの作業に含めない。
- 24KBの切り取りでは記事の予算・監修条件が欠落するため、既定モデルのみ40KBへ拡大。フォールバックは24KBを維持。固定評価の資源上限（項目6）のみこの設計へ合わせ、内容評価の基準は変更しない。
- 未定・不採用だけの単文資料、同じ生成言語の明示購入/予算条件はサーバー側でも保持する。語尾の書き換えや任意の「記載なし」削除は意味を壊すため行わない。実応答を最終整形処理で再生して評価する。
- 実評価はモデルごとの限られた例によるもので、統計的収束・全入力での正しさを主張しない。モデルの再生成で新たな細部の誤りが出る可能性は残る。
- 原文の再転記を内部draftに求める方式は、わずかな言い換えでも生成全体が失敗するため不採用。代わりに、本文を保持した根拠区間のIDを選んで短文を生成する。切断端と途中で省略したプロジェクト説明は根拠区間にしない。ラベル用1KiBを予約し、ラベル追加後も全体40KBを再検査する。
