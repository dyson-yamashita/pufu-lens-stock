# 本文に忠実な事実とプ譜構成の分離 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 可能性を実施予定へ、確認手段を必須合格条件へ強めず、記事の内容を短いプ譜として自動生成する。

**Architecture:** 事実の要約と目標・目的の構成を別のAI段階に分ける。先に本文・明示入力から実際の行動と現在の条件を短文化し、可能性・別事例を区別する。サーバーが採用対象の施策を抽出順に最大3群へ固定し、構成段階は各群の親目的とgoal/winだけを生成する。施策の取捨選択・再割当てをさせず、施策・八要素の表示文をサーバーが組み立てる。各段階を既存のaiStepで別々に計数・キャッシュする。

**Tech Stack:** TypeScript / Zod / Workers AI / D1 Workflow / Vitest

**Spec:** 本チャットの「本文より強い言い切りも修正して、記事に忠実な内容が自動生成されるように」。既存Draft PR169の続きとして実装する。

## Global Constraints

- 問い・ストックは各1件。本文を参照し、要約・切断端を確定事実の根拠にせず、個人・プロジェクトメモリを生成AIへ送信しない。
- 自動コメント・参考注記は追加しない。未知項目を一律に埋めず、既知の八要素を具体的に残す。
- 実施済み・予定・一般工程と、未選択の対応能力・将来の可能性・別事例を区別。入力の人数・予算・期限・禁止条件を弱めない。
- 事実抽出は入力40KB（旧形式モデル24KB）・出力6000tokens、構成は入力24KB・出力2000tokensで各1呼出し。構成へ本文を再送せず、短い抽出事実を渡す。追加呼出しも利用枠を消費する。
- 明示した獲得目標・手動コメント・保存済みデータを変更しない。マージ・本番反映はしない。

## Review Focus

- 将来の能力や別作品の選択を、現在の施策に採用できないこと。
- 構成モデルが施策・八要素を自由文で書き換えたり施策を省略・再割当てしたりできないこと。
- 生成途中の事実、構成結果、旧キャッシュを、本人・世代・privacy制御の外で再利用しないこと。
- 2段階目の利用上限や失敗時に、未完成のプ譜を保存せず、成功済み抽出を再実行しないこと。
- 言い換えが事実を強めないことを実モデルでも確認し、形式テストだけで完了にしないこと。

## 設計判断

根拠IDの実在確認と、同一モデルによる単純な合否照合だけでは、原文以上の必須性や将来保証を見逃した。事実の文を目標構成から分離して固定する方式を採る。意味の正しさを形式だけで保証したとは扱わず、記事との独立した比較評価を続ける。

実モデル比較でIDの取り違えと最終工程の脱落が残ったため、構成でのID選択を廃止して全施策を固定分配する。番号付きの群ごとに親目的を作り、行動がなければ目的・勝利条件は空にする。最終構成はKimi K2.6のnoneを既定とし、本文抽出はGLM-5.3のlowを使う。構成2000tokens・通常2callsの上限は変えず、別モデルを使った場合は両モデル名を記録する。
