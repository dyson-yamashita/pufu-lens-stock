# プフィの入口と「操作の迷い」の検知

目的は、エラーがなくても操作を探し続けている利用者に、任意で困りごとを伝える入口を示すこと。原因や困っている事実は検知だけで確定せず、利用者に尋ねる。

## 表示

プ譜の詳細・編集画面でパネルを閉じている間は、アイコンの左に「何かお困りですか？」を常設する。文字とアイコンのどちらでも手動会話を開く。会話・設定・自動案内を開いている間は重複する常設文を隠す。処理中・ダウンロード選択中は既存どおり非表示。ページと編集ダイアログの下部には常設案内のためのスクロール余白を確保する。

常設文は会話への入口であり、自動検知の同意や自動案内の回数制限を消費しない。自動案内を断った後も手動の入口は使える。会話を開いただけでは送信・保存せず、送信ボタンで保存とAI整理を行う。

## 発火条件

60秒の窓で評価し、異なる理由の合計3点以上を自動案内の候補とする。同じ理由は複数の操作があっても最大1件だけ。従来のトラブル条件は維持する。

| 分類     | 理由                              | 条件とスコア                                                                             |
| -------- | --------------------------------- | ---------------------------------------------------------------------------------------- |
| トラブル | rage_click                        | 8秒内の同じ操作への4クリックが応答されず、最後から1秒経過で3点                           |
| トラブル | validation_repeat                 | 同じ操作の入力エラー2回で2点、3回で3点                                                   |
| トラブル | operation_repeat / network_repeat | 同じ保存の失敗が同分類で2回で3点。通信・サービス障害は別理由                             |
| 迷い     | navigation_loop                   | 2局面への交互切替が4回で2点、6回で3点                                                    |
| 迷い     | exploration_repeat                | 同じ機能を進捗なく開閉2回で2点、3回で3点。対象は編集・JSON取込の詳細欄・ダウンロード選択 |

迷いの単独例は6回の交互切替、または同じ機能の3回の開閉。組合せ例は交互切替4回＋同じ機能の開閉2回で4点。比較のための通常の往復や1回の開閉だけでは表示しない。単なる滞在・待機には点数を付けない。止まっている人は常設文から任意で会話を開ける。

## 解除と抑止

入力イベント、保存・取込・ダウンロードの成功で迷いの全履歴と未完了の開閉候補を消す。入力内容は読まない。トラブル履歴は従来どおり該当操作の成功だけで消す。機能を開いたことは反応の通知であり、操作完了とは区別する。成功後の「閉じる」は開閉失敗に数えない。60秒窓を進めると3点→2点→0点へ再計算する。

明示同意OFF、入力中・処理中・非表示タブ・オフライン・初回案内中は自動表示しない。1セッション・24時間1回、断ると7日休止を維持する。検知はメモリ内の固定操作IDと時刻だけ。APIは理由enumを6種まで受け入れ、本人の会話送信時だけ保存する。Workers AIは迷いの検知も比較や試行の可能性として扱い、利用者の回答を優先する。外部登録は行わない。

## 検証

偽時計で閾値・解除・時間失効・重複開閉・同意OFF・待機だけの非発火を確認。実画面の開閉、局面切替、入力／保存後の解除をPC・スマホ幅で確認し、常設文の左右配置と手動会話、light/dark、マニュアルを撮影する。既存のトラブル検知・保存・頻度制御も回帰確認する。
