# 主要事例を保持するプ譜生成 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 一般工程を保ち、記事の主要事例の素材・判断理由・具体的処理を対象付きで残す。

**Architecture:** 既存2段階の抽出に最大3件の主要事例用データを追加する。根拠・対象・配置先を保持し、サーバーが既存の施策・八要素へ短く組み込み、構成AIへ記事タイトル・事例・品質条件を渡す。事例を利用者の実施予定や資源へ転用しない。

**Tech Stack:** TypeScript / Zod / Workers AI / Workflows / Vitest / existing E2E

**Spec:** 本会話で承認された修正方針（主題と適用範囲の保持、主要事例用抽出枠、構成への引継ぎ、正負両方の実モデル検証）。

## Global Constraints

- AIは既存の2呼出し、抽出40KB（他モデル24KB）/6000tokens、構成24KB/2000tokensを維持。
- 入力済みの目標を優先。保存形式・画面構成・既存保存済みプ譜を変更しない。
- 事例の対象と時制・留保を保持し、共通の必須条件に変えない。本文にない行動を追加しない。
- 自動コメント・参考注記を追加せず、既存の文章内へ対象名付きで配置する。

## Review Focus

- 根拠IDや対象が原文にない事例を採用しない。
- 明示された独自の目標・問いへの事例条件の転用をしない。
- 無関係な例・未選択の仕様・将来の可能性を実施済みへ変えない。
- 事例の追記で任意工程が必須工程に変わらず、完了工程が落ちない。
- 文章上限・空資料・旧Workflowの成功済みキャッシュからの再開を壊さない。

**Files:** `server/pufu-source-facts.ts`, `server/pufu-cases.ts`, `server/pufu-plan.ts`, `server/pufu.ts`, `tests/pufu-case-context.test.ts`, `tests/pufu-stage-resume.test.ts`

**Interfaces:** PufuFactsへ任意のcases配列（根拠ID・対象・本文・適用種別・八要素または工程番号）を追加。工程番号は抽出済み施策へ対応させ、サーバーで対象付きの短文を組み込む。旧キャッシュはcasesなしを許容する。

- [x] 対象付きの素材・品質・音声事例の保存と2段目入力、独自計画への転用禁止、不正根拠・対象・配置先・可能性・任意工程・上限のテストを追加し、REDを確認。
- [x] 主要事例を最大3件抽出し、根拠と対象を検証。タイトルと品質情報を構成へ引き継ぎ、全件の工程化を防ぐ。
- [x] 関連テストをGREENにし、旧キャッシュと2段階の計数・再開を検証。

## Decisions / progress

- 実装は本セッションで行う。独立レビューはリポジトリ規則どおり別エージェントへ依頼する。
- 記事整理（目標と問いが空）の事例を表示対象にする。独自の目標・問いがある場合も構成へ対象付き背景を渡すが、利用者の条件や施策へ挿入しない。

## Verification record

- 当該記事は実行時の本文snapshotを使用。実モデルの最終出力に35ミリの素材条件、グラデーション減少の可能性と質感の判断、音声のサラウンド化が対象名付きで残ることを確認。勝利条件は作品ごとの合意方針を保ち、事例の手法を全件条件にしない。
- 別題材は検証用の架空記事（録音デジタル化）を使用。素材・品質判断・具体処理の3事例を確認。独自の目標を入力したケースでは元記事の素材条件・処理を自分の条件へ移さず、明示目標を保持。
- 途中の実モデル応答ではJSON構文不正、配置偏り、対象名の見出し化を確認。配置は専用3枠へ固定し、根拠に実在する対象を検証。対象名補正は完全一致を優先し、既知見出し形だけに限定。意味の正しさを形式テストのみで保証したとは扱わない。
- 独立コードレビューの指摘（24KB入力枠の圧迫、DVD版等の限定脱落）を修正。共通工程だけを構成入力へ渡し、事例追記は保存用の文へ分離。回帰テストで再確認し、独立再レビューで対応必須指摘なし。
- マニュアル更新なし：操作・利用条件・既存説明に変更なし。仕様書とE2E台帳は内部生成処理に合わせて更新。
- ローカル関連CI E2EはChromium未導入で起動不可。公式取得先cdn.playwright.devが環境の通信ポリシーで403を返すため、ブラウザーシナリオの合格とは扱わずPRのCIでも確認する。
