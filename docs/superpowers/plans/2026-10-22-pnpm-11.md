# pnpm 11統一 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 開発・固定インストール・検証・監査・CI・デプロイ準備をpnpm 11.28.6へ統一し、監査専用の別バージョン呼び出しを削除する。

**Architecture:** ルートのpackageManagerを唯一のバージョン指定とし、既存のCI・デプロイはそれを参照する。監査スクリプトは通常のpnpm auditを呼ぶ。pnpm 11のインストール制約への互換設定を必要最小限追加する。

**Tech Stack:** pnpm 11.28.6、既存のNode.js 22.18以降の22系または24.11以降、GitHub Actions。

**Spec:** ユーザーの依頼「全体をpnpm 11に揃えて、監査だけ別バージョンを使う構成はやめてください」。

## Global Constraints

- PR #93の既存作業ブランチを継続し、既存のPDF対応を保持する。
- 依存バージョンを不要に変更せず、frozen-lockfileによる再現性を確認する。
- 監査のhigh基準とレジストリエラー時の失敗を維持する。
- 公開直後の既存固定依存が24時間制約で拒否される場合、該当固定バージョンだけを例外とする。全体の待機設定やビルド制限を無効にしない。
- 本番マージ・デプロイとグローバルなシェル設定変更は行わない。

## Review Focus

- 監査を含む全コマンドで同じpnpmが使用される。
- 新規環境でのfrozen install・ビルドスクリプトの許可/拒否が明示される。
- CIとデプロイでバージョン指定が分岐せず、Node.js要件とも整合する。
- README・現行仕様・PRの説明から旧構成が除かれる。
- 監査成功と、通信障害/脆弱性検出時の失敗が維持される。

## 実装・検証結果

- pnpm 11の初回固定インストールで、既存固定13パッケージの公開後24時間制約と `core-js-pure` の未承認ビルドをそれぞれ再現した。
- 公開待機の例外は `@goto-lab/pufu-editor@0.9.18` とcanvas本体・OS別の `1.0.13` だけに限定。`core-js-pure: false` で従来の未実行を明示し、他のビルド許可は維持した。
- pnpm 11.28.6で `CI=true pnpm install --frozen-lockfile` が成功。依存バージョン・ロックファイルの変更なし。
- 型チェック・lint・整形・通常ビルドが成功。全53ファイル・592テストが成功（`pnpm run test --maxWorkers=2`）。
- `pnpm run audit` は既知の脆弱性なし。ローカル模擬APIの503とhigh advisoryで、Bulk APIの利用と終了コード1を確認した。
- 検証用URL・リソースIDによる `pnpm run build:production` と `wrangler deploy --env production --dry-run` が成功。本番への反映なし。
- 利用者の操作・利用条件に変更がない内部改善のため、ユーザーマニュアルの追加更新は不要と判断した。
- 独立担当による未コミット差分全体の読み取り専用レビューを完了し、修正が必要な残存所見なし。
