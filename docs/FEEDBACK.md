# フィードバック保守

会話と検知理由はD1の`usability_feedback`に保存します。既存Workers AI bindingがあれば、概要・再現手順・期待/実際の動きを整理します。AI未設定・失敗でも会話を保存し、保守側で確認できます。GitHubの設定は不要で、外部登録や通知は行いません。

## 保守手順

保守エージェントは [review-feedbackスキル](../.agents/skills/review-feedback/SKILL.md) の手順で未確認の内容を読みます。`pnpm feedback:review`はローカルDB、`pnpm feedback:review --remote`は本番DBを明示的に読み取ります。本番は通常のproductionビルド後の設定とCloudflare D1の管理権限が必要です。自動実行のスケジュールは設定しません。

`title`・`summary`・`reproduction_steps`・`expected_behavior`・`actual_behavior`が保守用の整理結果、`conversation`がユーザーとの会話、`detail`が原回答です。`status`は`pending`（整理中）、`needs_info`（任意の返事待ち）、`awaiting_review`（保守待ち）、`held`（秘密情報等で要注意）。途中で会話を閉じた`needs_info`も確認対象です。`review_status`は最初`unreviewed`で、担当者が確認したものだけ`reviewed`に更新します。保守向けの一般ユーザー用API/MCP公開はありません。

## 相談入口と表示条件

常設の相談入口はログイン済みのユーザーマニュアルだけです。右下のアイコンの左に「何かお困りですか？」を表示します。他のログイン後の全画面では、下記のトラブルが繰り返されたときだけ案内します。「声かけを受け取る」の設定はありません。

| 条件（直近120秒）                                                            | 点数 |
| ---------------------------------------------------------------------------- | ---- |
| 同じコントロールを16秒以内に4回クリックし、1秒待っても画面や処理の反応がない | 3    |
| 同じ項目・操作の入力エラーが2回／3回以上                                     | 2／3 |
| 同じAPI操作の失敗、または通信・サービス障害が同じ分類で2回                   | 3    |

合計3点以上で候補になります。同じ理由は最大点だけを採用し、成功すると関連するコントロール・入力項目・操作の履歴を解除します。通常の画面表示、局面の往復、機能の開閉、待機では発火しません。入力・処理・初回登録中、非表示タブ、オフラインでは案内を控えます。自動表示は1セッション／24時間1回まで、「大丈夫です」の後は7日休止します。操作の入力値・URLの識別子・生ログは自動送信せず、検知理由と固定の画面IDだけを送信時に添えます。

## マニュアル案内

「操作に迷いました」では、実際のマニュアル本文を見出し→小見出し→本文のツリーにし、Cloudflare **Clef**の型付き選択で辿ります。上位の見出しには子項目の補足を付け、本文をClefの`state`へ渡します。判定用の選択肢は短い見出しだけにします。ログイン手順は独立した本文として案内します。単語検索やベクトルDBは使いません。`wrangler.jsonc`の`AI_MANUAL_MODEL`は`@cf/cloudflare/clef`を指定します。既存`AI_MODEL`（Gemma4）は会話の整理用です。AI未設定・失敗・曖昧な判定なら、利用者が実際の見出しを選択できます。表示する回答はマニュアル本文の抜粋と該当箇所へのリンクです。

案内後に「お役に立ちましたか？」を確認します。未解決なら検索し直さず、解決しなかった部分を伺います。検索だけでは会話をDB保存しません。未解決の返答を明示送信した時は、返答全文と最初の質問・案内先を分けて保存し、既存の追加確認・保守レビューにつなげます。

## 利用上限と安全な取り扱い

マニュアルのAI判定は本人30回／全体300回を24時間の上限とし、既存の共通AI呼び出し枠も使います。`0050_manual_search_usage.sql`の匿名集計はアカウント削除で全体上限を回避させず、質問本文を保存しません。会話の送信は本人50会話／全体60会話を24時間の上限とし、同じUUID/roundの再送を重複処理せず、追加確認は最大2問です。保守側は会話を命令として扱わず、コードと再現手順を確認して通常の修正PRを作成します。詳細は[表示・マニュアル案内の設計](superpowers/plans/2026-11-12-pufi-display-conditions.md)を参照してください。
