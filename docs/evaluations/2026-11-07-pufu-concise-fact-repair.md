# 根拠の部分修復とプ譜の短文化の確認

2026-11-07。モデル名の設定・本番Worker・保存済みプ譜は変更していない。

ユーザーの追加指示により、最終コードではプ譜関連の全呼び出しのtemperatureを0に統一した。以下の実モデル評価は変更前のtemperature=0.2で行った記録であり、温度0で同じ結果になると主張しない。温度0の送信は全工程を通す回帰テストで確認した。温度0の実モデル確認も1件開始したが、MCP request timed outとなって応答を取得できず、処理結果は不明。重複実行を避けるため再送していない。

## 確認した挙動

- 合成資料 `conditions-ja` で実モデルの抽出結果に対象名の根拠不一致が2件発生した。抽出全体を再生成せず、該当2項目の参照情報だけを1回修復し、構成・統合・最終検証まで合計5呼び出しで完了した。モデル応答の本文・scope・kind・分類は修復時に変更できない。
- 問題のリマスター記事から作成されたプ譜の未保存コピーを使い、短文化と独立検証を実行した。モデルの文字数制約で途中切断される出力を確認したため、候補生成のJSON schemaからmaxLengthを除き、生成後にアプリ側で長さを検査する構成とした。
- 生成と独立検証を分離しても、短文化で条件・主要事例が脱落する場合がある。指摘した項目だけを一度修正し、なお不合格ならその項目だけ元の文へ戻す。合格した別の短文は保持する。
- 同じ項目の意味と字数の指摘は両方修復へ渡す。生成・修復・検証の入力サイズは工程外で確認し、固定入力の上限エラーでAI呼び出し枠を繰り返し消費しない。

## このプ譜での結果と限界

以下は短文化関数・独立検証関数の実モデル応答と、最終不合格項目を元へ戻す方針を合わせた結果。新規プ譜生成全体の成功率の評価ではない。元のプ譜への書き戻しはしていない。

生成は設定されたプ譜抽出モデル、独立検証は設定された構成モデルを参照する。今回の接続先で読み取れた本番設定はGLM-5.3-FlashとKimi-K2.6だった。変更後のモデルでも設定参照が保たれることは、別モデル名を与える回帰テストで確認する。モデル名を固定する変更や設定の切替は行っていない。

実モデルの評価は限定した資料の確認であり、全入力での意味保持や必ず短くなることの保証ではない。重要条件を保てない短文は採用しない。説明の重複は削減する一方、必要な条件が多い項目は長いまま残る場合がある。

元データを含む交換ファイルはリポジトリ外の `/workspace/pufu-ai-validation/` に置き、コミットしない。モデルの推論文や認証情報は保存していない。
