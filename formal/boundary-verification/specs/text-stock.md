# B15 テキストストックの本文編集

[TextStock.lean](../BoundaryVerification/TextStock.lean) は [B01の認証モデル](auth.md) を使い、本人のWebセッションから本文を確定する遷移を扱う。

- [本文API](../../../server/api/routes/stock-details.ts) は要求時にセッションとOriginを確認し、現在のストックの所有者を照合する。MCPとショートカット用トークンの書き込みは許可表で拒否する。認証後の失効だけで実行中の要求を取り消す保証は対象外。
- [保存処理](../../../server/features/stocks/text-stock-content.ts) はD1の同じトランザクションで、現在のストック参照と記事の所有者・種類・世代を再確認する。ストックが削除された、別の記事を参照している、世代が変わった、のいずれかなら新しい本文を確定しない。同じ本文の再送は照会時に確認し、書き込まず成功を返す。
- 共有記事は新しい記事IDに分岐し、編集したストックだけを付け替える。単独なら記事IDを保持して世代を進める。新本文の保存、旧要約の解除、記事ジョブの登録、対象メモリ世代の失効は同じトランザクション。新しい要約の確定は [B08](jobs.md) が扱う。

| 性質                                                                                                   | 定理                                                                                                         | 実装との照合                                                                                                      |
| ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| 所有者・削除・種別・MCPとBearer・Origin・入力上限による拒否                                            | `foreign_stock_denied`、`removed_stock_denied`、`url_denied`、`delegated_edit_denied`、`rejection_reachable` | [本文APIのテスト](../../../tests/text-stocks.test.ts) で所有者・未認証・別Origin・Bearer/MCP・URL・本文上限を確認 |
| 参照記事・世代が古いときは本文、要約、ジョブ、関連を更新しない。同じ本文の再送で新しいジョブを作らない | `stale_article_denied`、`stale_generation_denied`、`same_body_does_not_write`                                | 同時編集の202/409、同文再送の200、再登録時のストック重複防止を実D1で確認                                          |
| 選んだストックだけを更新し、別の記事とストックの付随情報を保持。旧メモリの確定を止める                 | `shared_edit_changes_only_target`、`successful_edit_invalidates_memory`、`success_reachable`                 | 非公開側を編集後に匿名公開側の原文・索引IDを確認。タイトル・メモ・生成済みの問いとメモリ競合を照合                |

認証情報の検証、D1バッチの順序・原子性、外部キー、新規記事IDの一意性を前提とする。本文やストックの付随情報は識別値で表す。JSONの構文、文字数算定、検索索引の同期、R2の物理削除、AI出力の正しさ、実環境の全並行順序は定理の対象外。文字数の境界、分岐後の公開レスポンス、R2削除は実装テストで照合する。

[変異検出](../mutations/text-stock.json) では所有者、参照記事、世代、共有記事の分岐、メモリ世代の更新を一つずつ変更し、対応する定理の証明失敗を確認する。
