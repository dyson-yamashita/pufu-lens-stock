# ブラウザーE2E

[tester-army/e2e](https://github.com/tester-army/e2e) の公開版 `e2e@0.21.3` と `@e2e-dev/web@0.15.3` を使用します。e2eが固定するZodは既知の脆弱性を避けるため `e2e>zod: 4.6.7` へ限定overrideしています。実際のSPA、Worker、D1、R2、KVを起動し、desktop（1280×900）とphone（390×844）の両方で同じ結果を検証します。phoneはChromiumの狭い画面幅で、実機Safariの検証ではありません。既存の日本語フローはブラウザーの主言語を `ja-JP` に固定します。

## 初回準備

Node.js 22.22.3以降の22系、または24.11以降、pnpm 11.28.6が必要です。

```sh
pnpm install --frozen-lockfile
pnpm --filter @pufu-lens/e2e exec e2e-web install chromium --with-deps
pnpm run e2e:check
pnpm run e2e:ci
```

ブラウザーは公式SDKの通常起動を使います。独自のTCPデバッグポートや外部CDP接続は追加しません。

アプリは毎回ビルドします。動的loopbackポートと使い捨てのD1・R2・KVを使い、終了・中断時に削除します。既存の開発DB、本番リソース、Google認証、Workers AI、実サイトへの記事取得は使用しません。テスト用Workerには `.dev.vars` や本番のbinding・secretを引き継ぎません。通常のViteビルドが既存構成の `.dev.vars` を `dist/` へ複製する場合がありますが、テストはscratch内の新しい設定を使います。CIの失敗成果物に `dist/` は含めません。fixtureは既存のローカルデモログインと通常のAPIを使います。ブラウザーの外部originへの要求は遮断します。ビルド先の `dist/` を共有するため、E2Eを同じcheckoutで同時実行しないでください。

STOCK-002はscratch内だけのWorkerエントリーでDNSと外部HTTPをfixtureへ置き換えます。実際のURL検証・本文抽出・Workflow・D1・R2・デモ要約を使い、取得中を確認してから応答を解放します。fixture以外の外部HTTPは拒否します。取得失敗はHTTP 503で再現し、画面からの本文補完で回復します。外部サイトや実AIの品質は検証しません。QUESTION-001とSTOCK-002は通常のブラウザー操作で進め、追加の操作記録は不要です。

FIRST-001は通常のブラウザー操作で進め、追加の操作記録は不要です。初回ガイドのlight/dark表示を両画面幅でスクリーンショットに保存します。

これらの23シナリオで主要な操作を保護します。全機能・全APIの網羅、Googleログイン、外部AIの品質、iPhone実機を保証するテストではありません。既存のVitestによる権限・入力・競合・失敗時の検証も継続します。

LANG-001は使い捨てのローカル環境内で、通常APIからダミーのデモアカウントを削除・再登録し、初回登録を検証します。権限を限定したloopback URL以外には要求しません。フォーム操作は対象が明確な通常のブラウザー操作で行い、`agent.act` を使わないため追加の操作記録は不要です。既存3シナリオの6記録とAIを禁止するCIの検証は維持します。

## Codexで操作を記録する

```sh
codex login status
pnpm run e2e:record --scenario STOCK-001 --target desktop
```

ローカルの認証済みCodex CLIが画面からUI操作を選びます。モデルへ渡すのはダミーデータの画面と操作目標です。モデルの利用枠・通信が必要です。任意で `PUFU_E2E_CODEX_MODEL` を指定できます。検証に使用したCLIは0.159.2です。CLIがない・未認証・通信不可・操作失敗の場合は失敗として終了します。

2026-10-30時点で公式 `@e2e-dev/acp` は未公開のため、公開SDKの `StepExecutor` からCodex CLIを呼ぶ小さなアダプターを使用しています。空の一時ディレクトリ、read-only sandbox、ユーザー設定を読み込まない起動、shell/apps/plugins/web search等の無効指定、限定JSON schemaで操作を受け、画面に存在する対象だけへ操作を渡します。アプリのリポジトリやOAuth/APIキーをモデルへ渡しません。

既存の記録が使える場合はローカルでも再生します。操作を変えて記録し直すときは、失敗トレースに表示された該当の `recordings/<hash>.json` を削除してからrecordを実行してください。記録はe2eの実操作APIを通して作成され、後続の `expect` が通ったものだけ保存されます。JSONの手書き・合格条件の緩和で直さないでください。

初回導入の記録は、同じ実画面と `expect` を使う明示的なローカル専用 `pnpm run e2e:bootstrap` で作成できます。これはAIを呼ばない初期記録用executorです。Codexの利用可否とは独立して、実画面で確認された再生記録を用意できます。CIでbootstrapとrecordは拒否されます。

## CIではAIを使わない

CIは全23シナリオ×2画面幅を毎回実行します。記録はGitに含め、read-only/strictで再生します。AI executorを、呼ばれても必ず失敗するexecutorへ置き換え、モデル認証を設定しません。記録がない／古い／再生できない場合もAIに切り替えません。モデル呼び出し・消費ゼロ、選択した全ケースの単一attempt成功、skipなしをレポートから照合します。e2e本体の「skipでもexit 0」を成功として通しません。

GitHub Actionsはdesktopとphoneを別ジョブで並列実行します。各ジョブは専用のアプリ・D1・R2・KVを起動し、同じデモアカウントを使うシナリオ同士が競合しないよう、ジョブ内では順番に実行します。既存の品質チェック・Vitestとも並列で実行し、両画面幅を含むすべての検証結果を既存の必須Checkへ集約します。失敗時のレポートとトレースは画面幅別の成果物として7日保持します。`.e2e/` はGitに含めません。認証値や実ユーザーデータをfixture・記録・トレースへ入れないでください。

MEMORY-001は通常APIで2回のメモリ更新を待ち、R2に残った過去版と最新の表示切替・再読込を検証します。desktopとphoneの過去版画面をスクリーンショットとして保存します。

## HTMLで実行結果を見る

各実行後に `packages/e2e/.e2e/runs/<実行ID>/index.html` を自動生成し、ターミナルに場所を表示します。ブラウザーでファイルを開くと、成否・画面幅・実行時間・AI利用情報、展開できる操作手順を確認できます。失敗時は、保存されているスクリーンショットと操作履歴への相対リンクも表示します。

保存済みの結果から、テストやAIを動かさずにHTMLだけを作り直せます。

```sh
pnpm run e2e:report
pnpm run e2e:report --run <実行ID>
```

IDを省略すると最新のJSON結果を選びます。元のJSON・添付は変更せず、起動前に失敗して個別結果がない場合も、その状態をHTMLへ記録します。HTML作成に失敗しても、テスト失敗を成功にはしません。

HTML・JSON・添付を含む `.e2e/` はGit管理外です。レポートを別の場所へ渡す場合は実行フォルダー全体をコピーしてください。HTMLは外部スクリプトやサーバーなしで開けます。MEMORY-001は成功時も過去版画面、FIRST-001は初回ガイド、MCP-001は外部連携の3タブとスキル導入手順、THEME-001はトップページのlight/darkのスクリーンショットを保存します。USAGE-001は利用状況とマニュアルのlight/darkを両画面幅で保存します。その他のシナリオでは成功時のスクリーンショットや動画は保存しません。CIでは失敗時の既存成果物にHTMLも含まれます。

## 変更とテストを対応付ける

`scenarios.json` がID・担当ソース・検証観点の台帳です。

```sh
pnpm run e2e:check
pnpm run e2e:related --base origin/main
```

checkは実際の `e2e list` と台帳を照合し、重複ID、担当ファイルの消失、未登録テスト、片方の画面幅の不足、skip定義を拒否します。ブラウザーやAIは起動しません。relatedはmerge-baseからの追跡済み差分と未追跡ファイルを見ます。共通経路・設定・依存・未分類のアプリ変更は全ケースを選びます。対応がない文書変更は「未実行」と明示し、合格とは記録しません。ソースと台帳の対応は人が検証観点を判断して更新するもので、意味的な網羅を自動証明する仕組みではありません。

機能変更時は、該当IDの観点と実テストを更新し、必要ならローカルCodexで操作記録を更新します。同じ `expect` のままCIモードで再実行し、差分・記録をレビューしてください。失敗の詳細は `packages/e2e/.e2e/runs/<uuid>/report.json` と `results/*/trace.md` にあります。

## 導入時の検証記録（2026-10-30）

ローカルのChromium接続で3シナリオ×2画面幅の実行と、CIモードでの全6件再生・AI呼び出しゼロを確認しました。記録を1件外すと、CIがAIへ切り替えず失敗することも確認しました。初期記録はbootstrapで作成しています。認証済みCodex CLIの起動は確認しましたが、この実行環境ではモデル接続が失敗したため、ライブAIによる記録の成功は未確認です。監査で独自CDP起動の追加確認点が出たため、その代替起動を削除しました。最終版の通常起動はGitHub Actionsの必須Checkの検証対象です。
