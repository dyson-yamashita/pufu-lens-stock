# 問いの質と登録判断

## 判定の軸

| 軸       | 確認すること                                                             |
| -------- | ------------------------------------------------------------------------ |
| 根拠     | 実際に読んだストック・問い・本人の意見から、なぜ今問うのか説明できる     |
| 新しさ   | 近い既存問いと比べ、前提・成立条件・観点・判断のいずれかが具体的に変わる |
| 重要さ   | 答えが変わると、本人の理解や調べ方・判断が変わる                         |
| 開かれ方 | 特定の結論へ誘導せず、反例・別解を受け止められる                         |
| 焦点     | 一つの主な論点に絞り、抽象語や複数の疑問で大きく見せない                 |

全てを定量化する必要はない。新しい表現、広い抽象語、長い文章だけを新しさの根拠にしない。哲学的な問いも対象とし、全てを短期の行動や実験へ変換しなくてよい。

## 言い換えと掘り下げ

既存：「AI導入で生産性を上げるには？」

- 言い換え：「AIで仕事を効率化するには？」。実質同じ回答で済むので追加しない。
- 材料がある掘り下げ：「議事録作成が速くなっても納期が変わらないとき、作業時間と承認待ちのどちらが制約なのか？」。作業時間短縮と承認遅延のストック・本人コメントがあれば、制約の特定という論点が加わる。
- 根拠のない飛躍：「AIは人間の創造性を奪うのか？」。この材料からはつながらない。深そうな表現でも採用しない。

既存：「会議を減らして集中時間を増やすには？」。新しい資料も本人の経験もなく同じ主張しかない場合、仮説を確定した事実として追加しない。「会議を減らすとどこで困るか」などは本人への補助質問として使えるが、根拠ある新規候補と区別する。

## 意見の扱い

「ユーザーが言った」「記事が主張した」「AIが推測した」を区別する。対立する意見を平均して消さず、どの条件で違う結果になるかを問う。賛成を得たことを事実の検証と取り違えない。

## 保存前の確認

登録する各問いについて、最も近い既存問いとの差分、参照元、公開してよい本文、保存先を確認する。検索が途中・取得に失敗・本文が切れている場合は、その制約を結果に記す。無関係なストックを多数紐付けて根拠を多く見せない。

会話が英語の場合も同じ基準を適用し、候補・根拠・新しさ・次の手がかりを英語で説明する。保存済みの参照元のタイトルとIDは、取得したとおりに保持する。
